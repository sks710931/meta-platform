# Architecture cleanup report

Historical slice report; the current authentication and authorization rules are in [authentication.md](authentication.md).

Cross-cutting cleanup: WhatsApp Accounts owns its messaging/payment ID contract, and
Domain validation, Application error wording, and PostgreSQL constraints now agree on
opaque provider identifiers. No product features or public response shapes were added.

## Decisions

- Moved MessagingAccountId from Messaging.Contracts to WhatsAppAccounts.Contracts;
  updated Domain, Application, Infrastructure, and unit-test imports.
- Messaging is reserved for future Conversation, Message, OutboundMessage, and
  DeliveryStatus concepts; none were introduced.
- Removed the standalone onboarding Python smoke script. Its seven persistence and
  concurrency scenarios are retained in [future integration scenarios](future-integration-tests.md).
- External IDs preserve their exact value without numeric parsing, trimming, or case
  normalization. They require non-whitespace content, valid Unicode, at most 100 Unicode
  characters, and no control characters. A small internal validation helper keeps all
  three typed wrappers consistent.
- A forward TreatExternalIdentifiersAsOpaque migration replaces only the three external-ID
  check constraints. Historical migrations remain unchanged; the model snapshot and new
  designer were generated by EF. Internal UUID primary keys, global external-ID uniqueness,
  ownership FKs, session transitions, idempotency, concurrency, Development-only completion,
  and React behavior are preserved.
- PostgreSQL checks use explicit Unicode whitespace/control ranges to avoid locale-dependent
  character classes. Invalid Unicode cannot be stored in the UTF-8 database.

Rolling back this migration reinstates numeric-only constraints and will fail if newly
accepted nonnumeric identifiers are present. Review data before any downgrade.

## Tests changed

- Replaced External_identifiers_reject_malformed_values_instead_of_becoming_internal_ids
  with two small Fact tests in WhatsAppAccountTests:
  - External_identifiers_preserve_opaque_provider_values verifies all three wrappers accept
    nonnumeric, leading-zero, zero, Unicode, and 100-character boundary values unchanged.
  - External_identifiers_reject_missing_oversized_control_or_invalid_unicode_values verifies
    all three wrappers reject null, empty/whitespace, overlength, control characters, and
    invalid surrogate input; Unicode length boundaries are included.
- AggregateIdTests only changed its import following ID ownership; existing empty-ID coverage
  continues to protect MessagingAccountId.
- Deleted onboarding_smoke.py without mocked substitutes or integration infrastructure.
- All lifecycle tests remain unchanged. There are 22 deterministic unit cases in total.

## Verification

- Full .NET build: passed, zero warnings/errors.
- Unit tests: 22 passed, zero failed/skipped.
- React standalone TypeScript check and production build: passed; client sources unchanged.
- EF pending-model check: no pending changes.
- Generated idempotent migration SQL applied to the existing local PostgreSQL database,
  then reapplied successfully. All three external-ID unique indexes remain present.
- One-off SQL verification against the installed check definitions accepted opaque values
  and 100 Unicode characters, and rejected Unicode-only whitespace, control characters,
  and 101 Unicode characters. No test script or integration framework was retained.

No deviations from the requested scope. No Meta integration or other feature was started.
